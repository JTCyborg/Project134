# ami486.bin — CS:[8281] flag cross-reference audit

Date: 2026-11-17  
ROM: `ami486.bin`, 65,536 bytes, GitHub `main` (blob `480c7520c93e6c7ed437cf3ad214da7503f82ec6`).

## Result

The byte at `CS:8281` is a distinct flag byte from `CS:8280`.

- ROM image initial value: `CS:8280 = 2Fh`, `CS:8281 = 00h`.
- A repeated instruction pattern tests `CS:[8281] & 40h`: `2E F6 06 81 82 40`.
- The flag is therefore a global mode/feature gate consulted by multiple routines, not the CMOS-save gate previously documented at `CS:[8280] & 40h`.
- No direct write to `CS:[8281]` was identified in this pass. The found direct references are overwhelmingly TEST instructions. This does not rule out pointer-based writes, block copies, or initialization from another source.

## POST control-flow observations

At approximately `5272`, POST executes:

```asm
MOV AL,53h
OUT 80h,AL
TEST BYTE PTR CS:[8281],40h
JZ  clear_path
JMP  alternate_path
```

A second test occurs around `5478` and selects between another pair of paths. These are separate from the CMOS-save call at `52A0`:

```asm
MOV AL,57h
OUT 80h,AL
CALL 1C06h
MOV AL,58h
OUT 80h,AL
```

The CMOS routine at `1C06` still tests `CS:[8280] & 40h`; do not conflate the two flag bytes.

## Interpretation and remaining work

The repeated `CS:[8281] & 40h` checks strongly suggest a global execution-mode or CPU-capability switch: it influences POST branches and several low-level routines, including code in the final ROM segment around the protected-mode transition. The exact semantic name and the mechanism that sets it remain unproven.

Next steps:

1. Trace the two POST branches and identify the routines they select.
2. Inspect every confirmed TEST site to determine which CPU feature or execution path is gated.
3. Search for indirect writes/initialization of the byte at offset `8281` (pointer-based writes, copies, and table-driven setup).
4. Keep the flag's meaning provisional until the setter and all consumers agree.

No BIOS behavior or ROM bytes were changed.
