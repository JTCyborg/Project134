# AMI486 semantic map — phase 49 (2026-11-16)

## Scope

This phase corrects the alternate instruction boundary at `5C6A` and traces the status bits through the only direct entry into the `5BF8` POST memory-test chain. It also separates the bit-12 gate at `5C8C` from the bit-13 gate at `5CF9`.

## 1. Correct instruction stream after the 32-KiB test

The routine `552A–5571` performs four write/verify passes over `8000h` words. Its final pass writes and verifies `AX=0000h`. The RET at `5571` consumes the stack word at `5C66`, returning to `5C68`.

The stack word is `5C68h`, so the first instruction is `JNZ 5C2Eh` (bytes at 5C68–5C69 = `75 C4`). If ZF=0, it takes the failure path. If ZF=1, execution begins at `5C6A`, one byte later than the linear decode boundary.

Actual successful path:

| Address | Instruction | Effect |
|---|---|---|
| 5C6A | MOV AL,23h | AX=0023h because AH remains zero after final zero-pattern scan |
| 5C6C | OUT 80h,AL | POST checkpoint 23h |
| 5C6E | XOR byte [BP+DI],C0h | Modifies memory at BP+DI; this is the actual instruction alignment |
| 5C71 | MOV ES,AX | ES=0023h |
| 5C73 | MOV AL,40h | AX=0040h |
| 5C75 | MOV DS,AX | DS=0040h |
| 5C77 | MOV AL,30h | AX=0030h |
| 5C79 | MOV SS,AX | SS=0030h |
| 5C7B | MOV SP,0100h | Establishes new stack |
| 5C7E | CALL 1B5Eh | Calls one-byte RET stub |
| 5C81 | IN AL,60h | Reads keyboard-controller data port |
| 5C83 onward | JCXZ padding / OUT 80h | Timing/checkpoint sequence |
| 5C8C | TEST BP,1000h | Tests BP bit 12 |

There is no live `LES SI` on this successful path. The apparent `LES` at 5C69 is only the linear decoder's overlapping interpretation.

## 2. BP bit 12 and bit 13 are separate gates

At `5C8C`, BIOS executes `TEST BP,1000h`. If bit 12 is set, `JNE 5CF9` skips the keyboard-controller command sequence and goes directly to the bit-13 test.

If bit 12 is clear, the code sends command A1h to port 64h, polls via helper F602, reads port 60h, checks response values C8h/F2h and configuration byte CS:8280 bit4, and may send a further command through port64h. The code later sends command21h and performs a read/modify/write sequence through F622/F5BC.

At `5CC6` and `5CF0`, `OR BP,0` does not change BP; it only refreshes flags from BP. The final `5CF9 TEST BP,2000h` therefore tests the inherited BP bit13. If set, it sends command60h/data30h through F651 and jumps to D604. If clear, `5D07 AND BP,EFFFh` clears bit12 only; it does not set bit13.

This confirms that the `5C8C–5D07` block does not produce BP bit13. The source must precede entry to the `5BF8` chain (or be supplied by its caller/stack context).

## 3. The only direct entry into `5BF8` and BP mutations before it

The complete linear instruction listing has one direct transfer to `5BF8`:

- `DA9F JMP 5BF8`.

The relevant preceding code at `DA21–DA98`:

- Tests `CS:8280 bit7`.
- If the PIT/timer comparison at `DA1C` differs from `55AAh` and bit7 is set, `DA29 OR BP,1` sets only bit0.
- A later optional timing branch at `DA8D`, when bit7 is set and the measured interval is at least `0Ah`, executes `DA95 MOV BP,1` and jumps to the diagnostic handler `F4A5`; it does not reach `DA9F`.
- Otherwise execution reaches `DA9F` and enters `5BF8`.

Consequently, along the statically visible DA9F entry path, the local code can set BP bit0 but cannot set bit13. The DA95 assignment to BP=1 is on a path that leaves for F4A5 and does not enter the 5BF8 memory-test sequence.

## 4. What this says about BP bit 13

- `5C58 OR BP,BP` tests sign bit15.
- `5C8C TEST BP,1000h` tests bit12.
- `5CF9 TEST BP,2000h` tests bit13.
- `5CC6 OR BP,0` and `5CF0 OR BP,0` do not alter BP.
- `5D07 AND BP,EFFFh` clears bit12.
- `DA29 OR BP,1` only sets bit0.
- `DA95 MOV BP,1` sets BP to one but branches to F4A5, bypassing DA9F.

Thus BP bit13 is not generated by the visible DA9F→5BF8→5D07 path. It must be inherited at the entry point or supplied by a dynamic context not represented by a direct static branch. No proven producer for bit13 has been found yet.

## 5. Status and next target

### Confirmed

- Correct alternate decode of the successful `5C6A` path and exact segment values ES=0023h, DS=0040h, SS=0030h.
- Final zero-pattern scan in `552A` leaves AX=0000h, which explains why the AL-only segment setup works.
- Bit12 and bit13 are tested independently at `5C8C` and `5CF9`.
- The `5C8C–5D07` code does not set BP bit13.
- DA9F is the only direct linear-list transfer into 5BF8; its visible predecessor modifies only BP bit0 or diverts to F4A5 after setting BP=1.

### Unresolved

- The earlier producer/context for BP bit13 before DA9F.
- Whether DA9F is also reached through a computed/far entry not represented in the direct-transfer list.
- The live indirect entry into 8400h.

The 64-KiB ROM still has complete linear byte coverage, but semantic coverage remains incomplete because overlapping instruction streams, data tables, and stack-created continuations require path-sensitive decoding.
