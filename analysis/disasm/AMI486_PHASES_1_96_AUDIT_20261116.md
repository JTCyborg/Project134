## 2. Critical errors found and corrected

### 2.1 Dispatcher helper at 05E0h — false correction in phases 94–96

The raw ROM bytes at 05E0h are:

```
05E0  50 52 BA 03 12 E8 5D 02 5A 58 C3
```

Entry-aligned decode:

```asm
05E0  PUSH AX
05E1  PUSH DX
05E2  MOV DX,1203h
05E5  CALL 0845h
05E8  POP DX
05E9  POP AX
05EA  RET
```

Therefore the `CALL 05E0h` at the start of dispatcher 05B4h is **not** a RET-only stub. It is an active helper which preserves AX/DX and calls 0845h using the current SI text pointer. The separate entry at 05EBh is called on the dispatcher exit path at 05DBh.

Phase 92's original description of the 05E0h helper was correct. The later Phase 94 correction that reclassified 05E0h as a one-byte RET was false; Phase 95 repeated that error. The reports were corrected in place:
- Phase 92 now explicitly withdraws the false Phase 94 addendum.
- Phase 94 now distinguishes the 05E0h helper from the 05EBh exit entry.
- Phase 95 now records the real 05E0h instruction sequence.

The linked-record mechanics at 05B4h and the Phase 95 selected-base correction remain valid. The semantic details of the 05EBh entry should remain tied to its own instruction boundary and not be conflated with 05E0h.

### 2.2 ROM length in phase 60

Phase 60 said the ROM image was 65,534 bytes and labelled the reset-vector bytes `FF F0`. Both are incorrect. The checked-in image is exactly **65,536 bytes**; the reset-vector instruction begins at file offset **FFF0h** and the bytes are:

```
FFF0: EA 5B E0 00 F0
```

The phase-60 report was corrected in place. The reset path `FFFF0 -> F000:E05B -> D604` is retained.

### 2.3 Stale 5Dxx caller statement in DISASM_INDEX

The index contained a statement that the CALL at 5D54h targeted F5DBh. The instruction-aligned bytes show:
- 5D52h: CALL F5D9h
- 5D55h: MOV [0012h],AL
- 5D58h: TEST AL,20h

Phase 81 already contains the correct decode. The stale index statement is corrected in the index update accompanying this audit.

### 2.4 Disassembler metadata ambiguity

The index header said only “NASM ndisasm 3.01”, while the complete master listing's manifest and the checked-in GitHub Actions workflow identify **Capstone x86, 16-bit mode** as the generator for `ami486_full_linear_16bit.disasm.txt`. The index header is clarified to distinguish the historical archived listings from the Capstone-generated master listing.

## 6. Global status — do not confuse linear coverage with semantic coverage

- The ROM image is 65,536 bytes.
- The generated master listing mechanically accounts for 65,536/65,536 bytes.
- This proves byte coverage of a linear decode only.
- No complete audited byte-classification ledger yet partitions every offset into confirmed code, confirmed data, overlapping/alternate streams and unresolved bytes.
- No defensible whole-ROM semantic completion percentage can yet be calculated.
- The BP.13 producer and live entry into DA5Eh/DA61h remain unresolved.
- The 0AE1h selector entries 9, 11 and 13 remain raw overlapping record/callback cases; their targets are not semantically confirmed.
- Runtime provenance of optional OEM tables and several board-specific ALi1429 register meanings remain unresolved.

**Decision:** do not begin phase 97. The next work item is a ROM-wide address ledger and cross-reference reconciliation, driven by uncovered/ambiguous byte ranges rather than by incrementing a phase number.

## INT 13h table correction — 2026-11-16

The earlier byte-swapped-table hypothesis for A100h–A123h is withdrawn. The table begins at A0F1h, contains 26 native little-endian near offsets and ends at A124h. A08Dh is the INT 13h hard-disk handler; requests with DL<80h are forwarded to INT 40h. The corrected selector map is recorded in AMI486_STORAGE_AND_DISPATCH_REGIONS_20261116.md.


## INT 13h hard-disk subsystem progress — 2026-11-16

The A000h–AFFFh region is now mapped beyond the table level. A08Dh is the hard-disk INT 13h handler, A0A0h the AH dispatcher, and A0F1h–A124h the 26-entry function table. ## INT 13h/IRQ14/parameter-table wiring — 2026-11-16

The A95Eh installer replaces INT 13h with F000:A08Dh, saves the displaced vector in INT 40h, installs INT 76h/IRQ14 at F000:E845h, and configures INT 41h/INT 46h pointers to CMOS-selected 16-byte fixed-disk parameter records at E401h. A08Dh chains floppy requests (DL<80h) through INT 40h to the old BIOS INT 13h. E845h acknowledges both PICs and invokes INT 15h AX=9100h. This resolves the previously open ES:[01D8h] vector write and explains the hard-disk interrupt path.

## INT 14h entry alignment and BDA port lookup — correction (2026-11-16)

A second alignment pass corrected the earlier F9xx interpretation. The F900h seed was misaligned, and the first replacement at F8E8h was also one byte late. The verified guarded entry candidate is **F8E7h**, whose bytes are `83 FA 04` (CMP DX,04h). F8E8h is the ModR/M byte within that instruction, not an entry. The valid path starts at F8F2h.

The corrected stream shows:
- DX is a COM-port index 0..3, not a selector into the saved PUSHA register frame.
- DS is set to 0040h; `MOV DX,[DI]` after DI=2*DX reads the COM base word from the BDA array at 0040:0000+2*DX.
- A zero base branches to the restore path at F924h.
- The per-port timeout byte is read from 0040:007Ch+DX; its low byte is scaled by four into DI.
- AH selects one of six UART handlers through the table at F92Ah.
- The common cleanup CALL is at F926h and IRET at F929h; the table begins at F92Ah.
- F900h is the final displacement byte of the MOV at F8FDh, not a function entry.

The generator and seeded output were corrected and the new window was verified as F8E7h–F929h. The INT 14h IVT installation remains unverified. This correction supersedes the prior F8E8h and saved-register-frame wording in the earlier appended F9xx notes.

## FDC protocol findings — 2026-11-16

D499h was decoded through D1C0h/D243h/D270h: it sends exactly two command bytes, 4Ah and drive/head, then reads seven result bytes. This is the µPD765 MFM READ ID command. The AL values around D40Ah–D462h select data rate via 03F7h and are saved drive-state tokens, not FDC command bytes. D520h–D5D9h performs VERSION 10h (response 90h), DUMPREG 0Eh (ten result bytes), UNLOCK 14h, CONFIGURE 13h (00 08 00), PERPENDICULAR MODE 12h and LOCK 94h. D5DDh verifies the LOCK/UNLOCK result. These commands indicate an 82077AA-or-later 765-compatible feature set; they do not uniquely identify the fitted controller. Remaining gaps: low-bit [BX+90h] semantics, EEAAh configuration-byte provenance and the runtime INT 40h vector.
